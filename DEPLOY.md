# Запуск Lexab на Railway с доменом lexabai.com

Инструкция под конкретную задачу: сайт живёт на своём домене, работает целиком
как сейчас, но **открывается только по ссылке-приглашению** — для инвесторов и
конкурса на грант. Когда придёт время запускаться, сайт открывается публично
удалением одной переменной (шаг 8).

Выполняется по порядку. Всё, что нужно от вас, — браузер и файл `server/.env`
с вашего компьютера, откуда берутся ключи.

---

## Что получится

```
                lexabai.com  ──────────►  Railway, сервис «web»
   (браузер)                              сайт + гейт по ссылке
       │
       └──── api.lexabai.com ───────────►  Railway, сервис «api»
                                           Fastify, миграции при старте
                                                    │
                                    Supabase (база + файлы договоров)
```

Базу переносить не нужно: она уже в Supabase и останется там. Файлы договоров
тоже уже уходят в Supabase Storage (`SUPABASE_STORAGE_BUCKET=contracts`) — это
важно, потому что диск на Railway стирается при каждом перезапуске.

---

## Шаг 0. Почта — сделать ПЕРВЫМ

**Без этого шага демонстрация не состоится.** Регистрация не пускает в аккаунт,
пока человек не подтвердил почту (вход непроверенного пользователя отвечает
«Сначала подтвердите почту»). Письма сейчас уходят с адреса `onboarding@resend.dev` —
это тестовый отправитель Resend, он доставляет письма **только вам самому**.
Инвестор письма не получит и внутрь не попадёт.

1. Зайдите в [resend.com](https://resend.com) → **Domains** → **Add Domain** →
   `lexabai.com`.
2. Resend покажет несколько записей DNS (DKIM, SPF, иногда DMARC). Каждую
   добавьте в Cloudflare: **lexabai.com → DNS → Add record**, тип и значение
   копируются один в один. Для этих записей облачко должно быть **серым**
   (DNS only).
3. Дождитесь в Resend статуса **Verified** (обычно минуты, иногда до часа).
4. Запомните новый адрес отправителя — он понадобится на шаге 1:
   `MAIL_FROM=Lexab <noreply@lexabai.com>`

## Шаг 1. Railway: сервис API

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub
   repo** → выберите `imranprodead-cell/Lexab`, ветку `main`.
2. Откройте созданный сервис → **Settings**:
   - **Service Name**: `api`
   - **Root Directory**: `server`
   - Команды сборки и запуска трогать не нужно: они заданы файлом
     `server/railway.json` (`npm ci`, запуск `npm start`, проверка живости
     `/api/health`, **строго один экземпляр** — фоновые задачи вроде пакетного
     разбора не должны выполняться в двух копиях одновременно).
3. **Variables** → **Raw Editor** — вставьте переменные ниже. Значения со
   словом «из `server/.env`» скопируйте из этого файла на вашем компьютере,
   ничего не меняя.

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | из `server/.env` |
| `JWT_SECRET` | из `server/.env` |
| `DATA_ENCRYPTION_KEY` | из `server/.env` — **обязательно то же самое**, иначе уже загруженные договоры не расшифруются |
| `APP_BASE_URL` | `https://lexabai.com` |
| `CORS_ORIGIN` | `https://lexabai.com` |
| `TRUST_PROXY` | `true` |
| `API_PREFIX` | `/api` |
| `SUPABASE_URL` | из `server/.env` |
| `SUPABASE_ANON_KEY` | из `server/.env` |
| `SUPABASE_SERVICE_ROLE_KEY` | из `server/.env` |
| `SUPABASE_STORAGE_BUCKET` | `contracts` |
| `ANTHROPIC_API_KEY` | из `server/.env` |
| `DEEPSEEK_API_KEY` | из `server/.env` |
| `VOYAGE_API_KEY` | из `server/.env` |
| `RESEND_API_KEY` | из `server/.env` |
| `MAIL_FROM` | `Lexab <noreply@lexabai.com>` (после шага 0) |
| `ADMIN_EMAILS` | `imranprodead@gmail.com` — почта, у которой появится раздел «Админ-панель» |
| `SENTRY_DSN` | из `server/.env` (можно пропустить) |
| `GOOGLE_CLIENT_ID` | из `server/.env` |
| `GOOGLE_CLIENT_SECRET` | из `server/.env` |
| `GOOGLE_REDIRECT_URI` | `https://api.lexabai.com/api/auth/google/callback` |
| `GOOGLE_TTS_CREDENTIALS_JSON` | из `server/.env` (озвучка отчётов; можно пропустить) |

### Что НЕ переносить — и почему

| Переменная | Почему нельзя |
|---|---|
| `MAIL_REDIRECT_TO` | Вся почта клиентов ушла бы на один ящик. Сервер **не запустится**, если её задать: это защита от боевого запуска с отладочной настройкой |
| `PORT`, `HOST` | Railway задаёт их сам; своё значение сломает проверку живости |
| `BILLING_FALLBACK`, `LEMONSQUEEZY_*` | Удалены из проекта вместе с платёжным провайдером |
| `SEED_DEMO_PASSWORD` | Создаёт демо-аккаунт с известным паролем |
| `DROPBOX_SIGN_*`, `DROPBOX_APP_*` | Ключ песочницы перекрывает встроенную подпись и роняет её ошибкой. Раздел подписей и так выключен |
| `DATA_DIR` | Диск на Railway временный; файлы идут в Supabase Storage |
| `RAG_VALIDATE_MODEL` | Нужна только для ручных замеров качества поиска |

## Шаг 2. Railway: сервис сайта

1. В том же проекте: **New** → **GitHub Repo** → тот же репозиторий.
2. **Settings**:
   - **Service Name**: `web`
   - **Root Directory**: `/` (корень)
   - Команды заданы файлом `railway.json`, и там намеренно указана ТОЛЬКО
     сборка (`npm run build`). Зависимости Railway ставит сам, до этой команды.
     Добавлять в неё `npm ci` нельзя: вторая установка подряд падает с
     «EBUSY: resource busy or locked, rmdir /app/node_modules/.cache» —
     Railway держит этот каталог занятым под свой кэш.
3. **Variables**:

| Переменная | Значение |
|---|---|
| `VITE_SITE_ORIGIN` | `https://lexabai.com` |
| `VITE_API_BASE_URL` | `https://api.lexabai.com/api` |
| `VITE_USE_MOCK_API` | `false` |
| `SITE_ACCESS_CODES` | `invest-2026,grant-2026` — **это и есть коды приглашения**, придумайте свои |
| `SITE_GATE_SECRET` | любая длинная случайная строка (например, из `openssl rand -hex 16`) |
| `VITE_SENTRY_DSN` | значение `SENTRY_DSN` из `server/.env` (можно пропустить) |

Коды лучше завести разные по аудиториям — тогда доступ отзывается по одному:
убрали `grant-2026` из списка, и ссылки жюри перестали работать, а ссылки
инвесторов продолжают.

## Шаг 3. Домены

### В Railway

1. Сервис `api` → **Settings** → **Networking** → **Custom Domain** →
   `api.lexabai.com`. Railway покажет адрес вида `xxxx.up.railway.app` — это
   **цель CNAME**, скопируйте.
2. Сервис `web` → то же самое для `lexabai.com`. Railway даст вторую цель.

### В Cloudflare (lexabai.com → DNS → Add record)

| Тип | Имя | Содержимое | Облачко |
|---|---|---|---|
| CNAME | `@` | цель от сервиса `web` | **серое** (DNS only) |
| CNAME | `api` | цель от сервиса `api` | **серое** (DNS only) |

Серое облачко обязательно, пока Railway выпускает сертификат: через оранжевый
прокси проверка владения доменом не проходит. Когда в Railway рядом с доменом
загорится зелёная галочка, оранжевый прокси можно включить — но тогда в
Cloudflare **SSL/TLS → Overview** должно стоять **Full (strict)**, иначе получите
петлю переадресаций. Проще оставить серым: Railway отдаёт HTTPS сам.

Проверка через несколько минут — в терминале:

```bash
dig +short lexabai.com
dig +short api.lexabai.com
```

Обе команды должны вернуть адреса, а не пустоту.

## Шаг 4. Вход через Google

В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) →
ваш OAuth-клиент → **Authorized redirect URIs** → добавьте:

```
https://api.lexabai.com/api/auth/google/callback
```

Старую строку с `localhost` не удаляйте — она нужна для работы на вашей машине.

## Шаг 5. Проверка после запуска

```bash
# 1. Сервер жив
curl https://api.lexabai.com/api/health

# 2. Сайт закрыт для посторонних — должна прийти заглушка «по приглашению»
curl https://lexabai.com/

# 3. Поисковикам закрыто
curl https://lexabai.com/robots.txt      # ожидаем Disallow: /

# 4. Полный смоук боевого сервера (регистрация, публичные страницы)
BASE_URL=https://api.lexabai.com node server/scripts/smoke-prod.mjs
```

Затем откройте в браузере `https://lexabai.com/?k=invest-2026` — должен
открыться обычный сайт, а код исчезнуть из адресной строки. Зарегистрируйтесь
своей почтой и убедитесь, что **письмо о подтверждении пришло**: это главная
проверка шага 0.

## Шаг 6. Ссылки для инвесторов и жюри

```
https://lexabai.com/?k=invest-2026     ← инвесторам
https://lexabai.com/?k=grant-2026      ← жюри гранта
```

Что происходит у гостя: переходит по ссылке → браузер запоминает доступ на
30 дней → дальше сайт работает как обычный, ссылку можно больше не открывать.
Регистрация открыта: гость заводит аккаунт и проверяет продукт на своём
договоре.

Отозвать доступ:

- **одной аудитории** — уберите её код из `SITE_ACCESS_CODES`;
- **сразу у всех** — поменяйте `SITE_GATE_SECRET` на новое значение.

## Шаг 7. Что стоит знать про деньги

Регистрация открыта всем, у кого есть ссылка, а каждый разбор договора — это
запрос к платной модели. Если ссылка разойдётся шире, чем вы рассчитывали,
расходы вырастут. Подстраховки: бесплатный тариф ограничен (20 обращений к ИИ,
3 документа), в проекте есть общий потолок расходов на ИИ, а в админ-панели
(`/admin` под почтой из `ADMIN_EMAILS`) видно, кто регистрируется, и можно
менять лимиты конкретному аккаунту.

Если решите закрыть регистрацию совсем — скажите, добавлю флаг: вход только для
заранее заведённых аккаунтов.

---

## Шаг 8. Как открыть сайт публично (когда запускаетесь)

В сервисе `web` **удалите переменную `SITE_ACCESS_CODES`** (или оставьте пустой)
и дождитесь перезапуска. Всё: заглушка исчезнет, `robots.txt` снова станет
настоящим, поисковики увидят все 12 разделов. Код при этом не меняется — только
переменная.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| Сборка падает с `npm error Missing: … from lock file` | `package-lock.json` пересобран новым npm, а в Railway встроен npm 11.6. Пересоберите файл его версией: `npx npm@11.6.1 install --package-lock-only` |
| Сборка падает с `npm error EBUSY … rmdir '/app/node_modules/.cache'` | В `buildCommand` попал `npm ci`. Зависимости Railway ставит сам — в команде сборки должна остаться только сборка |
| Сборка падает с `VITE_SITE_ORIGIN не задан` | Не добавили переменную в сервис `web` |
| Сервер `api` не стартует, в логах «Небезопасные настройки для боевого запуска» | Перенесли `MAIL_REDIRECT_TO` — удалите её |
| Сайт открывается у всех подряд | `SITE_ACCESS_CODES` пуст. В логах при старте видно: «ОТКРЫТ ВСЕМ» или «доступ по ссылке, кодов: N» |
| Гость видит заглушку даже по правильной ссылке | Код в ссылке и в переменной различаются регистром или пробелом |
| Письма не приходят | Домен в Resend не подтверждён (шаг 0) или `MAIL_FROM` не на `lexabai.com` |
| В браузере ошибка про CORS | `CORS_ORIGIN` на сервисе `api` должен быть ровно `https://lexabai.com` |
| Вход через Google не возвращается | Не добавили адрес возврата в Google Console (шаг 4) |
