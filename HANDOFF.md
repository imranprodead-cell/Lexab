# Этап 1 (Британия) — сессия 2026-07-10 (утро)

## Сделано и проверено реальными запусками

**Корпус (миграция 014):** jurisdictions, legal_documents, legal_units,
court_cases, chunks, ingestion_runs. Provenance под CHECK-констрейнтами,
темпоральность valid_from/valid_to, pgvector включён на Supabase (0.8.2),
миграция не ломает PGlite-фолбэк (вектор-столбец条 условный).

**Ingestion UK (`npm run rag:ingest`):** 8 актов договорного права загружены
с legislation.gov.uk (CLML XML, реальный API): SGA 1979, UCTA 1977, CRA 2015,
Late Payment 1998, Arbitration 1996, C(RTP)A 1999, Misrepresentation 1967,
Limitation 1980. **2148 юнитов, 420 статей.** Иерархия Part→Chapter→
Pblock→Section→Subsection, «хлебные пути», официальные URI. Идемпотентность
проверена: повторный прогон — changed 0, unchanged 8.

**Индекс (`npm run rag:index`):** 417 чанков (статья целиком), у каждого
1–2 предложения ИИ-контекста (Haiku, temperature-стабильно). Эмбеддинги:
модуль готов (voyage-law-2, 1024); ждём ключ — `npm run rag:embed` после
появления VOYAGE_API_KEY в server/.env.

**Retrieval (`retrieveLegalContext`):** rewriting (Haiku, temp 0) →
citation fast-path (акт+секция → прямое попадание) → FTS строгий+мягкий →
(вектора, когда будут) → RRF → reranker-слот. Жёсткие SQL-фильтры
юрисдикции/даты.

**Валидатор цитат:** unit_id в находках анализа (schema-required), проверка
существования+действия+релевантности (Haiku temp 0, «правильная ли правовая
база»), спасательный проход по текстовой цитате, автопонижение unverified →
Low. Колонки findings.unit_id/unverified, отдаются фронтенду.

**Интеграция в продукт:** POST /analysis при юрисдикции UK тянет топ-10
провизий в промпт, после генерации валидирует цитаты. Проверено сквозным
анализом реального договора поставки: 4/6 находок ПОДТВЕРЖДЕНЫ (High/Medium
сохранены), 2 спорные честно unverified.

## Грабли

- fast-xml-parser: preserveOrder + trimValues:false обязательно (иначе
  склеиваются слова в инлайн-разметке CLML).
- plainto_tsquery = AND всех слов: длинные запросы давали 0 строк — поэтому
  есть мягкий OR-путь и citation fast-path.
- «s.9» токенизируется не как «9» — секцию по номеру ищем через
  legal_units.number, не через FTS.
- Пул Postgres не держит транзакции между query — атомарность ingestion
  через «чексумма пишется последней».
