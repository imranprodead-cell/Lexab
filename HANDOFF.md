# HANDOFF — статус проекта (обновлено 2026-07-21)

Актуальный, поддерживаемый статус. Детальные метрики RAG по юрисдикциям —
в CLAUDE.md («Статус этапов RAG»); этот файл — карта «что готово / что
осталось / как продолжать».

## Что готово (продукт)

- **Анализ договоров** с проверкой цитат по базе законов (валидатор в коде,
  не в промпте), чат по документу, сравнение версий, генератор договоров из
  шаблонов (обязательный бриф сделки), правка документов в воркспейсе.
- **RAG: 7 живых юрисдикций** — UK, UZ (20 актов, 3790 ст.), KZ, DE (BGB),
  US (федеральное: FAA, E-SIGN), CA (CCQ Квебек), AE (ГК ОАЭ). Гибридный
  retrieval (FTS+векторы+RRF+реранкер Voyage), golden-evals по каждой.
- **In-house функции**: плейбуки команды, CLM (сроки/обязательства/
  напоминания), массовый разбор, агентные воркфлоу, э-подписи (встроенные +
  Dropbox Sign), согласования, команда/роли, аналитика, аудит-лог.
- **Безопасность**: шифрование at-rest (KEK/DEK, crypto-shred), 2FA TOTP с
  анти-replay, DSAR-экспорт, retention-политика, access-review, брутфорс-
  алерты, immutable-аудит, ротация ключей. См. server/SECURITY.md.
- **Опс**: health с реальным SELECT 1, кластерные локи фоновых задач
  (безопасен мульти-инстанс деплой), heartbeat-recovery батчей/воркфлоу,
  graceful shutdown с дедлайном, Sentry на бэке и фронте (вкл. ErrorBoundary).

## Как продолжать

- Прод-деплой: скопировать server/.env.example → заполнить; миграции
  применяются при старте автоматически; перед деплоем можно прогнать
  `node --env-file=.env scripts/verify-db.ts` (проверка миграций/FTS/векторов
  на настоящем Postgres).
- Смоук после деплоя: `BASE_URL=https://api.домен node scripts/smoke-prod.mjs`
  (регистрация/health/публичные страницы; с SMOKE_EMAIL/SMOKE_PASSWORD —
  полный путь: логин → загрузка → анализ → отчёт; SMOKE_AI=1 тратит 1 ИИ-запрос).
- Правила работы, команды RAG и политика eval-отчётов — CLAUDE.md.

## Грабли (сохранено из ранних сессий)

- fast-xml-parser: preserveOrder + trimValues:false обязательно (иначе
  склеиваются слова в инлайн-разметке CLML).
- plainto_tsquery = AND всех слов: длинные запросы давали 0 строк — поэтому
  есть мягкий OR-путь и citation fast-path.
- «s.9» токенизируется не как «9» — секцию по номеру ищем через
  legal_units.number, не через FTS.
- Пул Postgres не держит транзакции между query — атомарность ingestion
  через «чексумма пишется последней».
- Supabase session pooler: ~15 сессий на проект. Сервер (PG_POOL_MAX=10) +
  скрипт рядом = отказ соединений; скрипты запускать с PG_POOL_MAX=2.
- DeepSeek v4 — рассуждающая модель: в микрозапросах thinking отключать
  (`thinking:{type:'disabled'}`), иначе max_tokens уходит в раздумья.

## Публичный сайт (12 страниц-разделов) — 2026-08-06

Сайт развёрнут из одностраничника в 12 разделов + переработанную главную.
Контент — данными (`src/content/pages/*.ts`, тип `Text6` требует все шесть
языков), один рендерер `src/pages/public/PublicPage.tsx`, реестр страниц
`src/pages/public/registry.ts`, реестр адресов `src/content/site/routes.json`.

**Домен — в ОДНОЙ переменной** `VITE_SITE_ORIGIN` (.env). Отсюда его берут
`index.html` (canonical/hreflang/og/twitter/JSON-LD через `%VITE_SITE_ORIGIN%`)
и `scripts/prerender.mjs` (canonical снимков, sitemap.xml, robots.txt).
Сборка ПАДАЕТ, если переменная не задана или в собранном HTML осталась
неподставленная `%VITE_…%`.

**Требование к хостингу:** статика должна отдавать `dist/<слаг>/index.html` по
адресу `/<слаг>` — в nginx это `try_files $uri $uri/index.html /index.html`.
Без этого краулер получит SPA-заглушку с пустым `<div id="root">`, а сайт при
этом будет ВЫГЛЯДЕТЬ рабочим (`vite preview` ведёт себя именно так — это его
ограничение, не дефект сборки).

**Замеры боевой сборки 2026-08-06:** первая загрузка публичной страницы
149 КБ gzip в 4 файлах (главный чанк 55 КБ, react-vendor 68, router 22,
css 6). Было 231 КБ — библиотека анимаций (48.7 КБ) уходила в первую загрузку
из-за жёсткого импорта `AppShell` в `src/router/routes.tsx`; теперь оболочка
кабинета грузится лениво.

**Упоры (сборка падает, а не предупреждает)** — `scripts/precompress.mjs`:
главный чанк ≤ 62 КБ, главный CSS ≤ 8 КБ, первая загрузка ≤ 160 КБ, и чанк
`motion` не должен попадать в первую загрузку. Плюс запрет в eslint:
`src/pages/public/**`, `src/components/public/**`, `src/content/**` не могут
импортировать motion/framer-motion и компоненты лендинга и кабинета.

**Тарифы — единый источник** `src/content/site/plans.ts`, сцеплен тестом
`plans.test.ts` с серверными `PLAN_LIMITS`/`PLAN_SEATS`: разойтись витрине и
серверу нельзя. Публичная страница `/pricing` числа не хранит вовсе — рисует
их блоком `kind:'plans'` из этого источника.

**Языковые адреса (/en/…) — задел, проверенный экспериментом 2026-08-06.**
Эксперимент (сделан и откачен): `URL_LANGUAGES = ['en']` в
`src/router/publicPaths.ts` + `...makePublicRoutes('/en')` в
`src/router/routes.tsx` → адрес `/en/pricing` открывается и рисует страницу.
ЧЕСТНАЯ ГРАНИЦА: этих двух правок хватает только на МАРШРУТЫ. Чтобы адрес
ЗАДАВАЛ язык, нужны ещё две вещи: ссылки строить как `publicPath(slug, lang)`
(сейчас вызываются без языка) и научить `I18nProvider` читать префикс адреса;
для снимков — записи по языкам в `routes.json`. То есть «включается в трёх
местах» — оптимистично: мест четыре плюс реестр.
