# SOC 2 / ISO 27001 — организационная часть (чеклист основателя)

Технические контроли реализованы в коде (см. SECURITY.md). Сертификат выдаёт
внешний аудитор ПОСЛЕ периода наблюдения, и половина требований — не код, а
организация. Этот файл — трекер того, что должен сделать основатель. Без
этих пунктов enterprise-опросники безопасности не пройти, какими бы хорошими
ни были технические контроли.

Статусы: [ ] не начато · [~] в работе · [x] готово.

## Политики (написать и утвердить; шаблоны продают Vanta/Drata/Secureframe, либо адаптировать открытые)

- [ ] Политика информационной безопасности (Information Security Policy)
- [ ] Политика допустимого использования (Acceptable Use)
- [ ] Политика управления доступом (Access Control: кто выдаёт/отзывает
      доступы, принцип наименьших привилегий; техчасть — access review в
      продукте — уже есть)
- [ ] Политика хранения и удаления данных (Data Retention — техчасть
      DATA_RETENTION_DAYS уже есть, нужна бумажная политика)
- [ ] Политика управления изменениями (Change Management: код-ревью, CI,
      кто может деплоить; техчасть — GitHub + CI — уже есть)
- [ ] Политика управления поставщиками (Vendor Risk: список субпроцессоров —
      Supabase, Anthropic, DeepSeek-хостинг, Voyage, Resend, Dropbox Sign,
      Sentry, хостинг — и оценка каждого; НЕ забыть отразить в Privacy Policy)

## Процессы

- [ ] План реагирования на инциденты (Incident Response: кто, что, в какие
      сроки; шаблон уведомления пользователей об утечке — GDPR даёт 72 часа)
- [ ] План непрерывности/восстановления (BCP/DR: бэкапы Supabase уже
      ежедневные — прописать RTO/RPO и процедуру восстановления, ОДИН РАЗ
      ПРОТЕСТИРОВАТЬ восстановление из бэкапа)
- [ ] Обучение сотрудников безопасности (пока команда = основатель: пройти
      и зафиксировать курс security awareness; при найме — процесс онбординга)
- [ ] Реестр рисков (Risk Register: раз в полгода пересматривать)

## Внешние проверки

- [ ] Пентест (перед серьёзными enterprise-сделками; бюджет ~$3–10k, отчёт
      прикладывается к опросникам)
- [ ] Выбор аудитора SOC 2 Type I → период наблюдения (3–12 мес.) → Type II

## Перед запуском (пересечение с launch-чеклистом)

- [ ] Ротация всех секретов, засветившихся при разработке
- [ ] privacy@ и security@ ящики на домене (privacy@ обещан в Условиях)
- [ ] DROPBOX_SIGN_TEST_MODE=0 (иначе подписи юридически не обязывающие)
- [ ] Проверить, что SEED_DEMO_DATA/ALLOW_INSECURE_SECRETS/LLM_FALLBACK
      пусты/выключены в проде
