# Legal RAG corpus — схема и правила (Этап 1)

Корпус проверяемых юридических текстов для LexAI. Живёт в той же Supabase
Postgres, что и приложение (`server/migrations/014_rag_corpus.sql`).

## Железные правила

1. **Только официальные источники** (белый список): legislation.gov.uk (UK,
   API/XML), caselaw.nationalarchives.gov.uk (UK практика, этап 2), lex.uz
   (UZ, этап 2), adilet.zan.kz (KZ, этап 2). Тексты законов НИКОГДА не
   генерируются моделью и не берутся из блогов/Википедии/агрегаторов.
2. **Provenance обязателен** — `source_url`, `retrieved_at`,
   `sha256_checksum` стоят под CHECK-констрейнтами: строка без источника
   физически не вставится.
3. **Темпоральность** — у каждой единицы `valid_from`/`valid_to`; retrieval
   фильтрует по дате действия редакции (`asOfDate`, по умолчанию сегодня).

## Таблицы

| Таблица | Что хранит |
|---|---|
| `jurisdictions` | UK / UZ / KZ: языки, формат цитирования |
| `legal_documents` | акт целиком: официальный ID (`ukpga/1979/54`), название, статус, checksum |
| `legal_units` | иерархия: part → chapter → section → subsection; «хлебный путь» (`UK / Sale of Goods Act 1979 / Part IV / s.14`), текст, даты действия |
| `court_cases` | судебные решения (заложено, этап 2) |
| `chunks` | единица поиска: **одна статья целиком** (никогда не режем посередине) + ИИ-контекст (Haiku) + tsvector + embedding (voyage-law-2, 1024) |
| `ingestion_runs` | журнал загрузок: получено/изменено/ошибок, diff в detail |

ID детерминированные: `lu_uk_ukpga-1979-54_section-14` — повторная загрузка
обновляет, а не дублирует.

## Пайплайны (`server/`)

- `npm run rag:ingest [-- --force | -- ukpga/1979/54]` — загрузка актов UK
  (пилот: 8 актов договорного права). Идемпотентно: чексумма XML
  сравнивается, без изменений — пропуск; чексумма пишется последней, обрыв
  посередине самовосстанавливается следующим прогоном.
- `npm run rag:ingest:uz [-- --force | -- 111181]` — загрузка законов РУз с
  lex.uz (русская версия): ГК часть 1 (111181) и часть 2 (180550), закон о
  договорно-правовой базе (10872), об ЭЦП ЗРУ-793 (6234906), о защите прав
  потребителей (14643). Классы разметки lex.uz: CLAUSE_DEFAULT = заголовок
  статьи, TEXT_HEADER_DEFAULT = раздел/подраздел/глава, ACT_TEXT = абзацы,
  COMMENTLEXUZ = редакционные сноски (пропускаются).
- `npm run rag:index [-- --docs=ld_uz_111181 --max-annotate=120]` — статьи →
  чанки + контекст 1–2 предложения (Haiku; для русских статей — по-русски).
  `--max-annotate` ограничивает расход: статьи сверх лимита индексируются без
  аннотации и дообогащаются повторным прогоном.
- `npm run rag:embed` — векторы Voyage (нужен `VOYAGE_API_KEY` в server/.env).
- `npm run eval [-- --retrieval-only | -- --model <id>]` — метрики; отчёты в
  `server/evals/reports/`.

## Retrieval (`server/src/rag/retrieve.ts`)

`retrieveLegalContext({ query, jurisdiction, asOfDate, topK })`:
query rewriting (Haiku, temperature 0) → «цитатный» прямой путь (акт+номер
статьи → мгновенное попадание) → полнотекстовый поиск (строгий AND + мягкий
OR) → векторный поиск (когда есть эмбеддинги) → reciprocal-rank fusion →
слот reranker (пока identity) → topK чанков с provenance.

Жёсткие фильтры юрисдикции и даты — в SQL, не пост-фильтрация.
Полнотекстовый поиск языкозависимый (миграция 015): русские чанки — русский
стеммер Postgres, английские — английский. Цитатный путь понимает оба стиля:
«Sale of Goods Act 1979, s.14» и «ст. 260 ГК» / «ст. 18 Закона «О защите прав
потребителей»».

## Валидация цитат (`server/src/rag/validate-citations.ts`) — правило в коде

Каждая находка анализа несёт `unit_id`. Валидатор: (1) юнит существует и
действовал на дату анализа; (2) Haiku подтверждает, что статья регулирует
вопрос находки; (3) находка без unit_id спасается разбором текстовой цитаты
(«…Act 1998, s.8» → юнит). Провал любого шага ⇒ `unverified: true` +
понижение до Low. Хранится в `findings.unit_id` / `findings.unverified`.

## Ограничения Этапа 1 (осознанные)

- Schedules (приложения к актам) не парсятся — только основной корпус акта.
- Хранится текущая действующая редакция (valid_from = RestrictStartDate);
  исторические редакции — этап 2 (схема готова).
- Reranker — заглушка; cross-encoder подключается без изменения вызовов.
- UZ/KZ — источники в белом списке, ingestion-модули не написаны.
